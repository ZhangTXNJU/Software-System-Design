# Feature Specification: 微型内存文件系统（迭代一）

**Feature Branch**: `001-micro-memory-filesystem`

**Created**: 2026-05-24

**Status**: Draft

**Input**: User description: "微型内存文件系统迭代一：命令行内存文件系统，支持 MKDIR、TOUCH、LS、INFO 四条指令。根目录 /，文件有名称和大小，目录有名称且大小为递归总和。迭代一不做路径规范化。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 创建目录结构 (Priority: P1)

用户通过 MKDIR 指令在内存中构建目录树。系统在指定绝对路径处创建目录节点；如果父目录不存在，指令被静默忽略（不输出、不改变状态）。

**Why this priority**: 目录是文件系统的基础命名空间，所有后续操作（TOUCH、LS、INFO）都依赖目录结构存在。

**Independent Test**: 连续执行多条 MKDIR 指令构造多层目录树，随后用 LS / INFO 验证目录存在且大小正确。

**Acceptance Scenarios**:

1. **Given** 空文件系统（仅有根目录 /），**When** 执行 `MKDIR /usr`，**Then** 根目录下出现名为 `usr` 的子目录，INFO / 的大小为 0。
2. **Given** 根目录下无 `/a`，**When** 执行 `MKDIR /a/b`（父目录 /a 不存在），**Then** 指令被忽略，不输出任何内容，文件系统状态不变。
3. **Given** `/usr` 已存在且为目录，**When** 再次执行 `MKDIR /usr`，**Then** 保持目录不变（no-op）。
4. **Given** `/readme.md` 已存在且为文件，**When** 执行 `MKDIR /readme.md`，**Then** 原文件节点被替换为同名目录节点。

---

### User Story 2 - 创建和覆盖文件 (Priority: P1)

用户通过 TOUCH 指令在指定路径创建文件并设定大小（整数，模拟字节数）。如果路径上已存在同名文件，则以新大小覆盖；如果路径上是目录，则用文件替换该目录。

**Why this priority**: 文件是数据存储的基本单元，INFO 的大小计算依赖文件节点的正确创建和覆盖语义。

**Independent Test**: 执行 TOUCH 创建文件，用 INFO 验证大小；再次 TOUCH 同名文件验证覆盖后大小变更。

**Acceptance Scenarios**:

1. **Given** 父目录 `/usr` 已存在，**When** 执行 `TOUCH /usr/test.txt 100`，**Then** 在 /usr 下创建大小为 100 的文件 `test.txt`。
2. **Given** `/readme.md` 已存在且大小为 50，**When** 执行 `TOUCH /readme.md 200`，**Then** 文件大小更新为 200（覆盖）。
3. **Given** `/usr` 已存在且为目录（含子节点），**When** 执行 `TOUCH /usr 50`，**Then** 原目录节点被大小为 50 的文件节点替换。
4. **Given** 父目录 `/a` 不存在，**When** 执行 `TOUCH /a/f.txt 10`，**Then** 指令被忽略，不输出、不改变状态。

---

### User Story 3 - 浏览目录内容 (Priority: P2)

用户通过 LS 指令列出指定路径下的所有直接子节点名称，按字母顺序输出。如果目标是文件，则只输出该文件自身的名称。

**Why this priority**: 浏览是验证文件系统状态的唯一可视手段，依赖于 P1 的创建操作但可独立测试。

**Independent Test**: 构造已知的目录/文件结构，执行 LS 并比对输出顺序和内容。

**Acceptance Scenarios**:

1. **Given** 根目录下有 `usr`（目录）和 `readme.md`（文件），**When** 执行 `LS /`，**Then** 按字母序输出 `readme.md` 和 `usr`（各占一行）。
2. **Given** `/readme.md` 是一个文件，**When** 执行 `LS /readme.md`，**Then** 仅输出 `readme.md`。
3. **Given** `/empty` 是一个空目录，**When** 执行 `LS /empty`，**Then** 不输出任何内容。

---

### User Story 4 - 查询节点大小 (Priority: P2)

用户通过 INFO 指令查询指定路径节点的大小。对文件直接返回其大小；对目录递归累加其子树中所有文件的大小。

**Why this priority**: 大小查询验证了文件系统数据完整性，依赖 P1/P2 的节点创建但可独立测试。

**Independent Test**: 构造已知大小的目录树，分别对文件和目录执行 INFO 并验证数值。

**Acceptance Scenarios**:

1. **Given** `/readme.md` 大小为 50 的文件，**When** 执行 `INFO /readme.md`，**Then** 输出 `50`。
2. **Given** 目录结构：`/usr/local/test.txt`(100) + `/readme.md`(50)，**When** 执行 `INFO /`，**Then** 输出 `150`（递归累加）。
3. **Given** 空目录 `/empty`，**When** 执行 `INFO /empty`，**Then** 输出 `0`。

---

### Edge Cases

- **非法路径（路径规范化禁区）**：路径中出现 `//`（连续斜杠）、路径以 `/` 结尾（且不是单独的 `/`）、路径段为 `.` 或 `..` 均视为非法路径；对应指令被忽略（不输出、不改变状态）。
- **文件↔目录覆盖**：TOUCH 可覆盖目录为文件；MKDIR 可覆盖文件为目录；MKDIR 对已存在目录是 no-op。
- **父目录不存在**：MKDIR 和 TOUCH 在父目录不存在时均忽略指令。
- **评测保证**：测试用例不会对不存在的路径执行 LS / INFO。
- **空目录 LS**：列出空目录时不输出任何内容。
- **LS 对文件**：对文件执行 LS 时仅输出该文件自身名称（而非"文件无子节点"的错误）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 从标准输入逐行读取指令，按指令执行后将输出写入标准输出。
- **FR-002**: 系统 MUST 支持 MKDIR 指令：格式 `MKDIR <绝对路径>`，在指定绝对路径创建目录节点；若父目录不存在则静默忽略（不输出、不改变状态）。
- **FR-003**: 系统 MUST 支持 TOUCH 指令：格式 `TOUCH <绝对路径> <大小>`，在指定路径创建文件并设定大小（整数）；若同名文件已存在则覆盖为新大小；若父目录不存在则静默忽略。
- **FR-004**: 系统 MUST 支持 LS 指令：格式 `LS <绝对路径>`，列出该路径下的所有直接子节点名称，按字母顺序每行输出一个；若目标为文件则仅输出该文件名。
- **FR-005**: 系统 MUST 支持 INFO 指令：格式 `INFO <绝对路径>`，输出节点大小（文件为自身大小，目录为递归子树中所有文件大小之和）。
- **FR-006**: 系统 MUST 以根目录 `/` 为唯一文件系统入口，所有路径均为绝对路径。
- **FR-007**: 系统 MUST 在迭代一中拒绝路径规范化：包含 `//`、以 `/` 结尾（非单独 `/`）、路径段为 `.` 或 `..` 的路径均为非法，相关指令静默忽略。
- **FR-008**: 系统 MUST 实现文件↔目录覆盖语义：TOUCH 在已有目录的路径上执行时用文件替换目录；MKDIR 在已有文件的路径上执行时用目录替换文件；MKDIR 在已有目录的路径上执行时保持目录不变。
- **FR-009**: 系统 MUST 在指令无法执行（父目录不存在、非法路径等）时静默忽略：不输出任何内容，不改变内存文件系统状态。

### Key Entities

- **文件系统（FileSystem）**：以根目录 `/` 为起点的树形结构，在内存中维护所有节点及其父子关系。
- **节点（Node）**：文件或目录的统称。具有名称属性和大小计算能力。
  - **文件（File）**：叶子节点，拥有名称和内容大小（整数，模拟字节数）。大小即为其内容大小。
  - **目录（Directory）**：容器节点，拥有名称和子节点集合。大小为其子树中所有文件大小的递归总和（不含目录自身）。
- **路径（Path）**：以 `/` 开头的绝对路径字符串，由斜杠分隔的路径段组成，指向文件系统中的一个节点。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 系统能正确解析并执行 MKDIR、TOUCH、LS、INFO 四条指令，输出与 OJ 评测用例预期完全一致。
- **SC-002**: 路径合法性判定严格按迭代一规则执行（拒绝 //、尾斜杠、.、..），无路径规范化行为。
- **SC-003**: 文件↔目录覆盖语义按题面「put 覆盖」模型实现，不因真实文件系统习惯而拒绝合法操作。
- **SC-004**: 目录大小递归计算正确，包含所有子孙文件大小，嵌套多层目录时无遗漏或重复。
- **SC-005**: LS 输出按名称字母序排列，每行一个节点名称，无多余空白行。

## Assumptions

- 输入指令格式严格遵循题面定义，不包含前导/尾随空白或空行。
- 文件大小值为正整数（或零），在整型范围内。
- 单次运行中指令数量在合理范围内（OJ 评测规模），无需考虑持久化或分布式场景。
- 实现语言和技术栈由开发者在迭代二前瞻建议的框架下自行选择（建议使用支持接口/抽象类的面向对象语言以便扩展）。
- 迭代二的功能（路径规范化、FIND、RM、LINK）不在本次交付范围，但代码结构应为后续扩展预留接口。
- 评测环境为 Gradescope 自动评测，输入输出严格比对。
